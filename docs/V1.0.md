# ResearchEvolve v1.0

v1.0 closes the last unaudited boundary between an executable empirical conjecture and its Lean target. Earlier releases required `ResearchSpec.metadata.formal_contracts` to contain a human-authored theorem signature. That path remains compatible, but the new certified semantic bridge can produce the target without giving a model authority to state what was proved.

## Certified semantic bridge

The bridge has four fail-closed stages:

1. `SemanticRegistry` binds each allowed `Predicate` field to a mathematical type, Lean binder, imports, semantic version, boundary vectors, the producing evaluator's SHA-256, frozen project fingerprint, and frozen premise-index fingerprint.
2. `PredicateIRCompiler` converts the v0.4 safe predicate DSL to a typed and scoped `MathExpr`. Registry schema 1 supports `Nat`, `Int`, and `Bool` values; `<`, `≤`, `>`, `≥`, `=`, and `≠`; and deterministic universal quantification. Unknown fields and scaled/offset references are `unsupported_semantics`.
3. `SemanticContractCompiler` derives the theorem name, binders, proposition, imports, toolchain, allowed axioms, and all provenance fingerprints. The proof model does not supply any part of the theorem signature.
4. `SemanticAuditor` independently reconstructs every contract field, validates type/scope, and differentially compares the empirical predicate with the IR over trusted boundary vectors and real candidate snapshots. Only a passed audit releases `certified_formal_contract`.

The contract and audit journal is `semantic_contracts.sqlite3`. Its identity is included in `formal_manifest.json`, so changing a registry or bridge configuration cannot silently resume an earlier formal run. The evaluator digest must also occur in the source research manifest; identical field names cannot hide changed Python semantics.

## Trusted registry

Validate and inspect a registry before use:

```bash
research-evolve semantic-registry \
  --registry examples/formal_project42/semantic-registry.json
```

Run the full v1.0 path with a `ResearchSpec` that contains no `formal_contracts`:

```bash
research-evolve formalize \
  --workspace .researchevolve/v10 \
  --tactic-generator-command "python examples/formal_project42/tactic_generator.py" \
  --project-root examples/formal_project42/lean_project \
  --project-lock examples/formal_project42/project-lock.json \
  --project-build-target FormalProject42 \
  --premise-index examples/formal_project42/premise-index.json \
  --semantic-registry examples/formal_project42/semantic-registry.json
```

`formal_verified` still comes only from the unchanged project-bound kernel gate: isolated Lake build, Lean compilation, axiom audit, and `leanchecker --fresh`.

## Portable research certificate

After a successful run, export a content-addressed evidence package:

```bash
research-evolve certificate-export \
  --workspace .researchevolve/v10 \
  --semantic-registry examples/formal_project42/semantic-registry.json \
  --project-lock examples/formal_project42/project-lock.json \
  --premise-index examples/formal_project42/premise-index.json \
  --output .researchevolve/v10-certificate
```

Structural verification checks the complete file manifest, SHA-256 digests, root fingerprint, registry/project/index lineage, semantic audits, proof lineage, and certified Lean source hash:

```bash
research-evolve certificate-verify \
  --certificate .researchevolve/v10-certificate
```

Supplying `--project-root` additionally rebuilds every certified theorem with `ProjectLeanKernel` and runs `leanchecker --fresh` in a new temporary workspace:

```bash
research-evolve certificate-verify \
  --certificate .researchevolve/v10-certificate \
  --project-root examples/formal_project42/lean_project
```

The verifier rejects path traversal, missing files, unmanifested files, content tampering, fingerprint drift, rejected semantic audits, broken formal lineage, and source/replay mismatches.

## Compatibility

The v0.6–v0.9 manual `formal_contracts` path remains available. v1.0 uses a certified generated contract only when no exact manual contract exists and `--semantic-registry` is supplied. Retrieval, proof-state search, budgets, resume behavior, and final Lean certification are otherwise unchanged.

# ResearchEvolve v0.5 — Proof Pipeline

v0.5 在 v0.4 的经验发现闭环之后增加独立证明阶段：

```text
Empirically Supported Conjecture
              │
              ▼
         Proof Preflight
   scan every valid CandidateDB row
              │
       counterexample?
        ┌─────┴─────┐
       yes          no
        ▼            ▼
     Refuted      ProofSpec
                      │
                      ▼
                 Proof Planner
                      │
                      ▼
                  Lemma DAG
                      │
                      ▼
                    Prover
                      │
                      ▼
                ProofArtifact
                      │
                      ▼
            Independent Verifier
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
       rejected   inconclusive  verified
                                  │
                                  ▼
                    verified_natural_language
```

证明阶段故意与 `research-evolve run` 分开。它读取已完成的 research workspace，并另外写入：

```text
proofs.sqlite3
proof_manifest.json
proof_summary.json
```

这样 Planner / Prover / Verifier 的非确定性不会改变 evolution 的 checkpoint 或 source `manifest.json`。

---

## 1. ProofSpec：冻结真正要证明的目标

`ProofSpec` 从 `empirically_supported` Conjecture 构造，包含：

```text
conjecture_id
statement
predicate
assumptions
evidence_candidate_ids
source generation
metadata
```

Planner 和 Prover 只能针对这个对象工作，不能偷偷：

- 弱化结论；
- 改变量范围；
- 改量词；
- 添加未声明条件；
- 把有限实验当作证明。

### 显式 proof assumptions

定义、归一化约定和公理不能由 Prover 临时编造。

v0.5 把两类前提冻结到 `ProofSpec.assumptions`：

1. source `ResearchSpec.constraints` 中的 hard constraints；
2. `ResearchSpec.metadata.proof_assumptions` 中显式声明的定义 / 公理。

例如：

```json
{
  "metadata": {
    "proof_assumptions": [
      "For every evaluated numeric candidate x, distance_to_42 is defined as abs(x - 42)."
    ]
  }
}
```

Prover 必须在 artifact 中声明实际使用了哪些前提：

```json
{
  "assumptions_used": [
    "For every evaluated numeric candidate x, distance_to_42 is defined as abs(x - 42)."
  ]
}
```

若 `assumptions_used` 中出现 ProofSpec 没有的前提，artifact 在进入 Verifier 之前直接 `invalid`。

> `proof_assumptions` 是研究者显式提供的输入，不是系统自动证明的事实。真实研究中应保证它们来自问题定义、已验证构造或可靠定理。

---

## 2. Proof preflight：证明前再找一次反例

在调用任何 proof model 之前，v0.5 会对 Conjecture predicate 重新扫描 **`candidates.sqlite3` 中所有 valid Candidate**。

如果已经存在违反 predicate 的 Candidate：

```text
Candidate
   │
   └── refutes → Conjecture
                     │
                     ▼
                  refuted
```

同时：

- 写入 v0.4 `Counterexample`，source=`proof_preflight`；
- 更新 source `summary.json` 的 conjecture/counterexample 统计；
- 不调用 Planner / Prover；
- 若这个猜想过去已有自然语言验证证明，则旧证明 lineage 全部失效。

proof preflight 不生成新 Candidate，也不重新执行 evaluator。主动反例搜索仍由 v0.4 research loop 负责。

---

## 3. ProofPlan 与 Lemma DAG

Planner 返回：

```json
{
  "strategy": "...",
  "lemmas": [
    {
      "label": "definition",
      "statement": "...",
      "depends_on": [],
      "role": "supporting"
    },
    {
      "label": "conclusion",
      "statement": "...",
      "depends_on": ["definition"],
      "role": "final"
    }
  ]
}
```

ResearchEvolve 确定性检查：

- strategy 非空；
- lemma 数量不超过 `--max-lemmas`；
- label 非空且唯一；
- lemma statement 非空；
- dependency 必须存在；
- 禁止 self dependency；
- dependency graph 必须无环。

Research Graph：

```text
ProofPlan
   ├── decomposes_into → Lemma A
   ├── decomposes_into → Lemma B
   └── decomposes_into → Lemma C

Lemma C ── depends_on → Lemma A
```

---

## 4. ProofArtifact

Prover 返回：

```json
{
  "lemma_arguments": {
    "definition": "...",
    "conclusion": "..."
  },
  "final_argument": "...",
  "assumptions_used": []
}
```

进入 Verifier 前，系统检查：

```text
每个 planned lemma 都有 argument
没有未知 lemma label
argument 非空
final_argument 非空
assumptions_used ⊆ ProofSpec.assumptions
```

结构不合法时状态直接是 `invalid`。

---

## 5. Independent adversarial Verifier

Verifier 收到：

- 原始 ProofSpec；
- ProofPlan；
- 完整 ProofArtifact；
- empirical evidence 作为上下文；
- 明确的 adversarial verification policy。

输出：

```json
{
  "decision": "verified",
  "issues": [],
  "confidence": 0.93,
  "adversarial_notes": "..."
}
```

决策：

```text
verified
rejected
inconclusive
```

Issue：

```text
error
warning
note
```

ResearchEvolve 再应用确定性 gate：

```text
Verifier says rejected
    → rejected

any issue.severity == error
    → rejected

verified + confidence >= threshold + no error
    → verified_natural_language

otherwise
    → inconclusive
```

因此 verifier 不能一边报告“这里有致命逻辑漏洞”，一边把结果强制标成 verified。

如果 Verifier 进程崩溃，系统会生成 synthetic `inconclusive` review，并把 ProofSpec / Plan / Artifact 同步为 `inconclusive`。

---

## 6. Prover / Verifier separation

Command actor 有两个不同用途的 identity：

### Config identity

用于 manifest / audit，考虑：

- actor role；
- 完整 argv；
- 引用脚本内容 hash。

### Independence identity

用于判断是否同一个底层实现。

如果存在直接引用的脚本文件，independence identity 主要基于：

- executable；
- 脚本路径 / 内容 SHA-256；

并忽略诸如 `--role prover` / `--role verifier` 这种角色参数。

因此：

```bash
python same_wrapper.py --role prover
python same_wrapper.py --role verifier
```

不能绕过独立性检查。

生产环境仍建议使用真正不同的模型 / worker / implementation。

---

## 7. Status semantics

v0.5 不引入模糊的 `proved` 状态。

```text
planned
drafted
verified_natural_language
rejected
inconclusive
invalid
```

最高状态：

```text
verified_natural_language
```

含义：

> 一个结构化自然语言 ProofArtifact 通过 ResearchEvolve 的结构/assumption 检查，并被独立 adversarial verifier 接受。

它不等于：

```text
Lean checked
Coq checked
Isabelle checked
SMT certified
kernel verified
formal_verified
```

---

## 8. Stale proof invalidation

自然语言验证结果必须可撤销。

如果某个猜想过去已经：

```text
verified_natural_language
```

之后 CandidateDB 中出现独立评测过的新 Candidate 并在下一次 proof preflight 中形成反例，系统会级联失效：

```text
Conjecture    → refuted
ProofSpec     → invalid
ProofPlan     → invalid
Lemma         → invalid
ProofArtifact → invalid
ProofReview   → invalid (gated status)
```

原始 `ProofReview.decision` 仍保留在 SQLite payload 中用于审计，表示“当时 verifier 做过什么判断”；但它不再代表当前有效证明状态。

---

## 9. ProofMemory

`proofs.sqlite3` 包含：

```text
proof_specs
proof_plans
proof_artifacts
proof_reviews
```

Research Graph 新增：

```text
proof_spec
proof_plan
lemma
proof_artifact
proof_review
proof_actor_error
```

典型 lineage：

```text
Conjecture
    ▲
    │ targets_conjecture
ProofSpec
    ▲
    │ plans_for
ProofPlan
    │
    ├── decomposes_into → Lemma A
    ├── decomposes_into → Lemma B
    └── decomposes_into → Lemma C

ProofArtifact
    ├── implements_plan → ProofPlan
    └── claims_proof_of → ProofSpec

ProofReview
    ├── reviews → ProofArtifact
    └── supports_natural_language_proof_of → Conjecture
```

关系故意叫 `claims_proof_of`，因为未验证 artifact 不应被当成 theorem。

---

## 10. proof_manifest.json

独立 proof manifest 锁定：

```text
source research-run fingerprint
planner config identity
prover config identity
verifier config identity
prover independence identity
verifier independence identity
max_conjectures
max_lemmas
evidence_context
min_verifier_confidence
```

如果同一个 workspace 后续换了 actor 或 proof policy，ResearchEvolve 会拒绝把新 run 静默混进旧 proof journal。

# CLI

## 第一步：生成可证明的支持猜想

proof42 使用专用 spec，其中显式提供距离定义：

```bash
research-evolve run \
  --spec examples/proof42/spec.json \
  --evaluator examples/target42/evaluator.py \
  --seeds examples/proof42/seeds.json \
  --conjecturer-command "python examples/conjecture42/conjecturer.py" \
  --workspace .researchevolve/proof42 \
  --islands 2
```

## 第二步：运行证明管线

```bash
research-evolve prove \
  --workspace .researchevolve/proof42 \
  --planner-command "python examples/proof42/planner.py" \
  --prover-command "python examples/proof42/prover.py" \
  --verifier-command "python examples/proof42/verifier.py" \
  --max-conjectures 4 \
  --max-lemmas 24 \
  --min-verifier-confidence 0.7
```

## 检查 proof journal

```bash
research-evolve proof-specs --workspace .researchevolve/proof42
research-evolve proof-plans --workspace .researchevolve/proof42
research-evolve proof-artifacts --workspace .researchevolve/proof42
research-evolve proof-reviews --workspace .researchevolve/proof42
research-evolve proof-manifest --workspace .researchevolve/proof42
```

# v0.5 仍然不做什么

v0.5 尚不提供：

- Lean / Coq / Isabelle compilation；
- theorem formalization；
- proof-kernel checking；
- formal proof repair；
- citation-grounded theorem retrieval；
- multi-verifier quorum；
- symbolic proof checking beyond domain evaluator。

推荐下一阶段 **v0.6**：

```text
verified_natural_language
        ↓
Formalizer
        ↓
Lean theorem + lemma skeletons
        ↓
Lean kernel/compiler
        ↓
errors / unsolved goals
        ↓
Proof Repair Loop
        ↓
formal_verified
```

# ResearchEvolve v0.4 — Observation → Conjecture → Counterexample

v0.4 在 v0.3 的 evolutionary + semantic research loop 之上加入第二条研究闭环：

```text
Evaluated Candidates
        ↓
ObservationExtractor
        ↓
Structured Observations
        ↓
Conjecturer / LLM
        ↓
Testable Conjecture Predicate
        ↓
Archive Counterexample Scan
        ↓
Mutation-based Counterexample Search
        ↓
┌───────────────────────┬───────────────────────┐
│ counterexample found  │ no counterexample yet │
│                       │                       │
▼                       ▼
refuted            empirically_supported
│                       │
└──────────────┬────────┘
               ↓
       next Conjecturer context
               ↓
       refine / replace conjecture
```

## 设计原则

### 1. 猜想不是“自然语言结论”

每个 `Conjecture` 必须同时包含自然语言 `statement` 和机器可测试 `Predicate`。

例如：

```json
{
  "statement": "distance is non-negative",
  "predicate": {
    "left": {"source": "metrics", "key": "distance"},
    "operator": "ge",
    "right_constant": 0
  }
}
```

系统的经验测试以 predicate 为准；自然语言 statement 用于研究解释和图谱展示。

### 2. 不执行任意模型表达式

v0.4 不允许 Conjecturer 提交 Python 表达式。

`ValueRef.source` 只能是：

```text
score
payload
metrics
behavior
```

比较运算只能是：

```text
lt  <
le  <=
gt  >
ge  >=
eq  ==
ne  !=
```

右侧可以是 JSON constant，也可以是另一个 `ValueRef`。

ResearchEvolve 不使用 `eval()` / `exec()` 解释猜想。

### 3. 有限实验永远不等于证明

v0.4 的状态只有：

```text
proposed
empirically_supported
refuted
invalid
```

不存在 `proved`。

只要找到一个通过 evaluator 的 candidate 使 predicate 为 false，该猜想立即进入 `refuted`。

如果没有找到反例，并且达到 `min_evidence` 个可测试样本，只能进入 `empirically_supported`。

真正的 theorem / proof / verifier 会属于后续 proof pipeline。

# 核心对象

## Observation

`ObservationExtractor` 从当前可信 search archives 提取确定性摘要，例如：

- canonical score range
- metric range
- behavior dimension 的不同取值

示例：

```json
{
  "kind": "metric_range",
  "statement": "Metric distance was observed in [0, 42] across 8 candidates.",
  "evidence_candidate_ids": ["..."],
  "data": {
    "metric": "distance",
    "minimum": 0,
    "maximum": 42,
    "count": 8
  }
}
```

Observation 是经验事实摘要，不是 theorem。

## Conjecture

```json
{
  "statement": "score is always negative",
  "predicate": {
    "left": {"source": "score"},
    "operator": "lt",
    "right_constant": 0
  },
  "observation_ids": ["observation-..."],
  "evidence_candidate_ids": ["candidate-..."],
  "parent_conjecture_ids": [],
  "rationale": "...",
  "confidence": 0.6
}
```

`parent_conjecture_ids` 用于表达 refinement：

```text
Conjecture A
    │
    └── refined_into
            ▼
       Conjecture B
```

## Counterexample

Counterexample 必须对应一个**已被独立 evaluator 验证为 valid** 的 Candidate。

```json
{
  "conjecture_id": "conjecture-...",
  "candidate_id": "candidate-...",
  "source": "archive",
  "payload": {...},
  "metrics": {...},
  "score": 0.0
}
```

来源可能是：

```text
archive
counterexample_search
```

# Counterexample Search

v0.4 使用两层策略。

## Layer 1：已有 archive 扫描

先测试当前：

```text
MAP-Elites elites
Pareto frontier
Novelty archive
```

如果历史研究结果已经包含反例，不再浪费额外 evaluator 预算。

## Layer 2：主动搜索

如果已有 archive 没有反例：

```text
sample parent
    ↓
FourLevelMutator
    ↓
new candidate
    ↓
Evaluator Cascade
    ↓
Conjecture Predicate
```

由 `conjecture.counterexample_trials` 控制额外尝试次数。

主动找到的 candidate 同时进入：

- Candidate DB
- MAP-Elites / Islands
- Pareto Archive
- Novelty Archive
- Research Graph

因此“攻击猜想”本身会产生新的研究数据。

# Conjecturer Protocol

v0.4 提供 provider-neutral `Conjecturer` 接口和 `CommandConjecturer`。

CLI：

```bash
research-evolve run \
  --spec research.json \
  --evaluator evaluator.py \
  --seeds seeds.json \
  --conjecturer-command "python my_conjecturer.py"
```

Conjecturer 从 stdin 接收：

```json
{
  "schema_version": 1,
  "count": 2,
  "context": {
    "problem": "...",
    "generation": 5,
    "objectives": [],
    "constraints": [],
    "observations": [],
    "candidates": [],
    "conjectures": []
  },
  "response_contract": {...}
}
```

输出：

```json
{
  "conjectures": [
    {
      "statement": "...",
      "predicate": {
        "left": {"source": "metrics", "key": "distance"},
        "operator": "ge",
        "right_constant": 0
      },
      "observation_ids": ["..."],
      "evidence_candidate_ids": ["..."],
      "parent_conjecture_ids": [],
      "rationale": "...",
      "confidence": 0.8,
      "metadata": {}
    }
  ]
}
```

外部 Conjecturer 无权指定 ResearchEvolve 内部 node ID。外部返回的 `id` 会被剥离，仅作为 metadata 中的 `external_conjecture_id` 留存审计。

# ResearchSpec

新增：

```json
{
  "conjecture": {
    "enabled": true,
    "interval": 1,
    "observations_per_interval": 12,
    "conjectures_per_interval": 2,
    "context_candidates": 24,
    "context_conjectures": 12,
    "counterexample_trials": 8,
    "min_evidence": 3,
    "timeout_seconds": 60
  }
}
```

字段含义：

| 字段 | 含义 |
|---|---|
| `enabled` | 是否启用猜想循环 |
| `interval` | 每多少 generation 运行一次 |
| `observations_per_interval` | 单次最多提供多少 observation |
| `conjectures_per_interval` | 单次最多产生多少猜想 |
| `context_candidates` | 猜想上下文 candidate 数量上限 |
| `context_conjectures` | 历史猜想反馈数量上限 |
| `counterexample_trials` | archive 扫描之后的主动反例搜索预算 |
| `min_evidence` | 标成 empirically_supported 所需测试数 |
| `timeout_seconds` | 外部 Conjecturer 超时 |

# Persistence

新增：

```text
.researchevolve/run/
├── candidates.sqlite3
├── ideas.sqlite3
├── conjectures.sqlite3
├── research_graph.sqlite3
├── checkpoint.json
├── manifest.json
├── pareto.json
└── summary.json
```

`conjectures.sqlite3` 内部包含：

```text
observations
conjectures
conjecture_tests
counterexamples
```

保存每一个 candidate test，而不是只保存累计数字，目的是支持可靠的 checkpoint resume。

# Resume 语义

假设 checkpoint 停在 generation 5，但程序在 generation 6 已经产生部分猜想/反例后崩溃。

恢复时：

```text
restore generation 5 search archive
        ↓
prune IdeaMemory > generation 5
        ↓
prune Observation / Conjecture / Tests / Counterexamples > generation 5
        ↓
recompute surviving conjecture status
        ↓
resume generation 6
```

Conjecture context 只来自 checkpoint 恢复后的 MAP-Elites / Pareto / Novelty archives，不会直接读取 CandidateDB 中可能残留的半截 generation candidate。

# conjecture42 demo

无需 API key：

```bash
research-evolve run \
  --spec examples/conjecture42/spec.json \
  --evaluator examples/target42/evaluator.py \
  --seeds examples/conjecture42/seeds.json \
  --conjecturer-command "python examples/conjecture42/conjecturer.py" \
  --workspace .researchevolve/conjecture42 \
  --islands 2
```

Demo Conjecturer 故意提出两个猜想：

1. `score < 0`：因为 seed 中有 `x=42`、score=0，应立即被反例推翻。
2. `distance_to_42 >= 0`：在有限实验中应积累 empirical support。

目的不是证明关于绝对值的数学定理，而是验证完整状态机：

```text
observation
  ↓
conjecture
  ↓
test
  ↓
counterexample/refutation
```


# v0.4 的边界

v0.4 是**经验猜想研究系统**，不是 theorem prover。

它可以可靠地做：

```text
从实验归纳 observation
生成机器可测试 conjecture
寻找 counterexample
拒绝被击穿的 conjecture
保留尚未被击穿的 empirical hypothesis
把失败反馈给下一轮研究
```

它不能仅凭有限测试宣称一般数学命题已经证明。

下一阶段适合加入：

```text
v0.5
Conjecture
   ↓
Proof Plan
   ↓
Lemma decomposition
   ↓
Prover
   ↓
Adversarial Verifier
```

也就是从实验发现正式进入 proof pipeline。

# ResearchEvolve v0.8

v0.8 upgrades v0.7's frozen lexical premise index into a deterministic, auditable formal-retrieval and proof-search layer.

## Declaration database

Premise index schema 2 stores, for every frozen Lean declaration:

- declaration name, module, kind, source path and line;
- normalized type features such as `nat`, `le`, `eq`, `arrow`, `forall` and `exists`;
- explicit dependencies on other declarations in the same frozen index.

The full database remains bound to the exact `LeanProjectLock` fingerprint and receives its own content fingerprint. Schema 1 indexes remain readable for compatibility, but newly built indexes use schema 2.

## Goal-conditioned hybrid retrieval

Ranking combines:

1. inverse-document-frequency lexical overlap;
2. structural/type-feature overlap with the current theorem goal or Lean diagnostic state;
3. dependency-graph expansion from high-ranking declarations.

The selector never widens the frozen import allowlist. `allowed_modules=[]` still means no available premises; only explicit preview calls may use `None` for unrestricted search within the frozen index.

## Proof-search budget

Every selection is bounded by `ProofSearchBudget`:

- candidates scanned;
- results returned;
- dependency expansions;
- serialized context characters.

The decision journal records the configured budget, actual usage, exhaustion flags, score components, retrieval depth, goal state and repair round.

## Repair-time retrieval

The first Formalizer call is conditioned on the frozen theorem signature. After a kernel rejection, v0.8 builds a new retrieval query from the Lean diagnostics and stderr and searches for premises not already supplied. The Repairer context reserves up to half of its result slots for prior premises, uses the remaining slots for fresh diagnostic-conditioned results, and enforces the same total context-character budget. This expands the search without discarding every useful lemma found in an earlier round.

Retrieval stays advisory. Only the frozen Lake build, Lean compile, axiom audit and `leanchecker --fresh` path can grant `formal_verified`.

## CLI

```bash
research-evolve premise-search \
  --premise-index premise-index.json \
  --query "distance nonnegative" \
  --goal "⊢ 0 ≤ d" \
  --module FormalProject42.Premises \
  --limit 12 \
  --candidate-budget 5000 \
  --dependency-budget 8 \
  --context-budget 24000
```

The same budgets are available to `formalize` as `--premise-candidate-budget`, `--premise-dependency-budget`, and `--premise-context-budget`.

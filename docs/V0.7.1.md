# ResearchEvolve v0.7.1 audit fixes

v0.7.1 is a narrow correctness patch produced by re-auditing v0.7 before starting v0.8.

## Fixes

1. **Empty premise allowlists are now actually empty.** `PremiseSelector.select(..., allowed_modules=[])` no longer falls back to unrestricted retrieval. `None` is the only unrestricted mode and is used only by explicit preview/search flows. This restores the v0.7 trust policy that a formalization can retrieve only from modules frozen in `FormalizationSpec.imports`.

2. **Lake `packagesDir` is honored.** Dependency capture and exact project materialization now read the frozen `packagesDir` from `lake-manifest.json` instead of assuming `.lake/packages`. Non-default dependency directories inside the frozen project root are supported and excluded from root-source scanning to avoid double-counting dependency sources.

3. **External dependency cache directories remain fail-closed.** A `packagesDir` that escapes the project root (for example `../shared-packages`) is rejected by the certification path because v0.7 cannot content-address and materialize it without widening the frozen project boundary.

4. **Malformed lock file lists are rejected.** Non-object entries in `files` or `dependency_cache_files` now fail validation instead of being silently dropped.

## Compatibility

The lock schema remains v2. Existing default-layout v0.7 locks keep the same fingerprint semantics. The path of the dependency cache is already committed to the lock indirectly through the content hash of `lake-manifest.json`; v0.7.1 merely interprets that frozen manifest field correctly when locating and materializing dependency bytes.

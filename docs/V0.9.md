# ResearchEvolve v0.9

v0.9 replaces whole-proof-only generation with an optional interactive Lean proof-state search runtime. It keeps every v0.8 trust boundary: search may propose proof-body tactics, but only `ProjectLeanKernel` may issue `formal_verified` after a clean compile, axiom audit, and `leanchecker --fresh` replay.

## Structured interaction

`LeanProofState` records every open goal, local context, case name, cumulative tactic history, parent, depth, and a semantic fingerprint. `FrozenLeanProofWorker` evaluates each cumulative tactic prefix inside one isolated copy of the content-addressed `LeanProjectLock`. A rejected tactic affects only that branch.

The worker appends trusted `trace_state`/`sorry` instrumentation to probes so Lean reports unfinished goals. This instrumentation is never returned by a tactic generator and never enters a `FormalArtifact`. If a probe contains a `sorry` warning but no parseable goals, the worker fails closed instead of reporting a false terminal state.

## Bounded best-first search

`ProofSearchFormalizer` provides:

- goal-conditioned premise retrieval for every expanded state;
- best-first frontier ordering with a bounded beam;
- semantic state deduplication and tactic-attempt caching;
- independent state, depth, tactic, Lean-call, model-call, retrieval-call, wall-clock, and beam budgets;
- a SQLite journal in `formal_search.sqlite3`;
- exact-config recovery of searches interrupted while their status is `active`;
- a distinct `search_exhausted` outcome rather than conflating bounded failure with an invalid artifact.

Completed tactic histories are reconstructed as a proof term and handed to the unchanged certification pipeline. A closed search state is therefore only `formalized`; it becomes `formal_verified` only after final project-bound kernel replay.

## CLI

Interactive mode requires a frozen project and matching premise index:

```bash
research-evolve formalize \
  --workspace .researchevolve/run \
  --tactic-generator-command "python tactic_generator.py" \
  --project-root path/to/lean-project \
  --project-lock project-lock.json \
  --premise-index premise-index.json \
  --project-build-target MyProject \
  --search-resume
```

The tactic actor receives `action=propose_lean_tactics`, the frozen formal specification, the structured current proof state, state-conditioned retrieved premises, and a candidate limit. It returns a `candidates` array containing one-line tactics, confidences, premise names, and optional rationales. Declarations, `sorry`/`admit`, metaprogramming, commands, and multiline boundary escapes are rejected before Lean is invoked.
